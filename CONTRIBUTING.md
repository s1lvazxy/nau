# Contributing to Nau

Thank you for looking. Nau is small enough to read in an afternoon, and it should stay that way.

## Getting it running

```bash
pnpm install
pnpm dev                 # http://localhost:3100, local mode: data stays in your browser
supabase start && pnpm setup:local   # optional: the database, for connectors, the API and the scheduler
pnpm test                # unit tests
supabase start && pnpm test:int   # the same plus Postgres, the server path and a stand-in shop
pnpm typecheck && pnpm build
```

## How the code is laid out

- `src/lib` — domain types, Portuguese rules (NIF, IVA, holidays, AT export), analytics.
- `src/data` — the change set (the only way data changes), undo, the local and cloud backends.
- `src/ingest` — the one door for outside data: spreadsheets, SAF-T, photos, connectors and the API all become a batch.
- `src/connectors` — one file per outside system. See `docs/connectors.md`.
- `src/agent` — Operator: tool schemas, executors, the policy and journal, the offline engine.
- `src/server` — everything that needs secrets: sync, the public API, the scheduler, the headless Operator.
- `src/routes` — pages and server routes. `src/routeTree.gen.ts` is generated by the router plugin and committed; `pnpm dev` or `pnpm build` refreshes it. `supabase/migrations` — the database.

## What a good change looks like

- **One write path.** Data changes through a `ChangeSet`. If you need to write some other way, open an issue first.
- **Idempotent by construction.** Anything that comes from outside gets an id derived from the source's own reference.
- **Operator obeys the policy.** A new write tool goes through `propose()`. It never applies a change directly.
- **Tested where it can break.** Pure logic gets a unit test; anything touching Postgres or the server path gets an integration test.
- **Plain words.** Interface copy is short, specific and free of jargon. The website and onboarding are in Portuguese (Portugal); the app is in English for now, and translation is welcome.
- **No new dependency without a reason** stated in the pull request.

## Connectors

The most useful contribution is a run of a beta connector against a real account, with what you found. New connectors are welcome: follow `docs/connectors.md`, and include tests built from the vendor's documented responses.

## Security

Please do not open a public issue for a vulnerability. See `SECURITY.md`.
